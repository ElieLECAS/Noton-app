## P0.4 — Un seul appel LLM avant le retrieval ✅

**Avant** : `decide_guided_mode` (1) + fused understanding (1) + `generate_queries` (1) =
**3 appels LLM** avant le premier hit.

**Après** : le fused understanding porte TOUT (route, signaux, condense, topic_shift,
vagueness **+ décision guidée** is_guided/flow_kind/product_named/needs_intent_clarification/
detected_symptom), et les requêtes retriever sont construites **sans LLM** → **1 seul appel**.

- `lightweight_query_understanding.py` :
  - `_guided_prompt_block()` : bloc de prompt guidé (vocabulaire symptômes SAV) ajouté au
    fused quand `GUIDED_DECISION_IN_FUSED` + `GUIDED_FLOW_ENABLED`.
  - `_parse_guided_fields()` : normalise les 5 champs guidés du JSON.
  - `GuidedDecision` (+ `LightweightQueryResult.guided`) : décision guidée propagée.
  - `_node_build_queries_fast()` : requêtes colpali/semantic/lexical déterministes
    (question autonome + entités/refs), branché quand `QUERY_GENERATE_QUERIES_LLM=false`.
  - Validation JSON du fused + **1 retry** si tronqué / sans clé `route` (P0.3).
- `query_reasoning_service.resolve_guided_mode()` : dérive la décision du fused (0 LLM) ;
  retombe sur `decide_guided_mode` si le fused ne l'a pas produite (QU off / échec / tests).
- `chat.py` : orchestration réécrite — **reprise** guidée active (0 LLM) → fiche technique
  (0 LLM) → **fused** (1 LLM) → **nouveau départ** guidé (réutilise la décision du fused).
  Helper `_guided_streaming_response` factorisé (2 points d'entrée), `_guided_anchor_ids`.
- Trade-off modèle documenté : la décision guidée passe sur `MODEL_QUERY_UNDERSTANDING`
  (mistral-small). Si la détection se dégrade → pointer cette variable vers un modèle plus
  capable, ou `GUIDED_DECISION_IN_FUSED=false` (decide_guided_mode dédié sur MODEL_FAST).

## P0.2 — Robustesse du flux de génération ✅

- **Fallback Mistral 400 re-ciblé** : au lieu de rejouer le contexte CAG massif (cause
  probable du 400), 3 tentatives dégressives full → **CAG re-packé eco** (`_build_eco_context`,
  budget `CAG_ECO_TOKEN_BUDGET`, `CAG_ECO_MAX_DOCUMENTS`) → question nue.
- **Filtre `<sources>` réinitialisé** à chaque tentative de secours (plus d'état de capture
  résiduel entre fallbacks).
- **Boucle de stream factorisée** : `_stream_llm_to_sse` (émission + filtre + accumulation)
  remplace les 3 copies de la boucle SSE dans le générateur RAG.
- **Réponse partielle persistée avec marqueur** : une génération interrompue à mi-stream est
  sauvegardée avec `metadata_json={"response_truncated": true}` — plus de texte affiché mais
  absent de la base.
- **Persistance avec retry** (`_persist_reply_with_retry`) : une écriture DB qui échoue ne
  perd plus silencieusement la réponse.

## P0.3 — Budgets temps + dégradation visible ✅

- **Timeout applicatif sur les appels LLM de compréhension** (`_understanding_chat`,
  `QUERY_UNDERSTANDING_TIMEOUT_S=25s`) : plus de blocage avant retrieval si Mistral lag.
- **Validation JSON du fused + 1 retry** (cf. P0.4) : plus de fallback silencieux sur JSON
  invalide.
- **Budget temps global du retrieval** (`RETRIEVAL_TIMEOUT_S=90s`, généreux pour ne pas
  couper un ColPali légitime) : un canal qui freeze → dégradation gracieuse (0 passage,
  statut `degraded_timeout`) au lieu d'un hang.

## Nouvelles clés de configuration

| Clé | Défaut | Rôle |
|---|---|---|
| `QUERY_GENERATE_QUERIES_LLM` | false | true = requêtes retriever par LLM (au lieu de déterministe) |
| `GUIDED_DECISION_IN_FUSED` | true | décision guidée portée par le fused (0 appel dédié) |
| `QUERY_UNDERSTANDING_TIMEOUT_S` | 25 | budget temps d'un appel LLM de compréhension |
| `RETRIEVAL_TIMEOUT_S` | 90 | budget temps du retrieval complet (0 = off) |
| `CAG_ECO_TOKEN_BUDGET` | 20000 | budget du contexte de secours (fallback 400) |
| `CAG_ECO_MAX_DOCUMENTS` | 3 | plafond documents du contexte de secours |

Toutes ont un défaut sûr côté code + compose : rien à ajouter dans `.env`.
