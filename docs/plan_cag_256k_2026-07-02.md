# Refonte CAG post-retriever — exploiter la fenêtre 256k de Mistral Large

> Objectif : le retriever ne sélectionne plus des *passages*, il sélectionne des **documents**.
> La génération reçoit des documents entiers (ou sections entières), en ordre de lecture,
> jusqu'à un budget de ~100–150k tokens. Le rappel passe du niveau passage (difficile)
> au niveau document (beaucoup plus facile) : il suffit que le bon document soit dans le top-D.

---

## 0. État actuel du retriever (post-modifications du 2026-07-02)

```
message → compréhension fusionnée (1 appel LLM : route + signaux + condense + topic_shift)
        → 4 retrievers EN PARALLÈLE (ColPali / pgvector / BM25 / KAG), pool 40 par canal
        → fusion RRF (RRF_K=60)
        → boost catégorie (plafonné ×1.5)
        → ✂ COUPE À RAG_TOP_K = 8   ← space_search_service.py:913 (compose: RAG_TOP_K:-8)
        → expansion voisins (± 1 page)
        → format passages : page entière (≤12k chars/passage, budget global 80k chars)
        → génération (max_tokens 2048)
```

**Pourquoi toujours 8 sources** : les changements précédents ont augmenté la *profondeur* de
chaque source (page entière au lieu de 4 000 chars) mais pas leur *nombre* — la coupe
`fused_hits[:top_k]` à 8 pages reste le goulot. Rectification vs le plan précédent : cette
coupe existe bien même reranker OFF (ligne 913).

**Budget réellement consommé aujourd'hui** : ~8 pages × ~2-4k chars ≈ 20–30k chars ≈
**6–9k tokens**, soit **~3 % de la fenêtre 256k**. Il y a un facteur ×15–20 disponible.

## 1. Vision cible : « Document-CAG »

### Principe

1. **Le retrieval devient un sélecteur de documents.** Les 4 canaux votent page par page ;
   on agrège les votes par document → top-D documents (6–10).
2. **Le contexte devient un dossier documentaire.** Pour chaque document retenu :
   - document **entier** s'il tient dans le sous-budget (la plupart des notices font 4–20
     pages ≈ 3–15k tokens → rentrent facilement) ;
   - sinon **sections entières** autour des pages matchées (fenêtre de pages élargie).
3. **La génération lit comme un technicien** : documents complets, dans l'ordre de lecture,
   avec en-têtes explicites (gamme, matériau, fournisseur, type de doc) et marqueurs de page.

### Pourquoi ça améliore le rappel

- Aujourd'hui : il faut que le *bon chunk/page* soit dans le top-8 → sensible au moindre
  défaut de ranking (boost, requête reformulée, vocabulaire).
- Demain : il faut que le *bon document* soit dans le top-6/10 documents. Un document
  reçoit des votes de TOUTES ses pages matchées sur 4 canaux → signal beaucoup plus stable.
- L'information « en page 9 alors que le match était en page 7 » est incluse d'office
  (document entier) : plus de réponses « la notice ne précise pas » alors que c'est 2 pages
  plus loin.
- Les tableaux coupés entre pages, les renvois (« voir page 15 »), les légendes → résolus
  par construction.

## 2. Architecture détaillée

### 2.1 Nouveau service : `app/services/context_packer_service.py`

```
pack_cag_context(session, final_hits, *, token_budget, signals) -> CagContext
```

**Étape A — Agrégation par document**
- Regrouper les `UnifiedPageHit` par `document_id`.
- Score document = `max(rrf_score des pages)` + `0.2 × Σ(rrf des pages suivantes)` +
  bonus multi-canaux (pages vues par ≥2 canaux) — favorise les documents à la fois
  « fortement » et « largement » matchés.
- Trier, garder top `CAG_MAX_DOCUMENTS` (défaut 8).

**Étape B — Packing glouton sous budget**
Budget global `CAG_TOKEN_BUDGET` (défaut 100k tokens ≈ 350k chars ; estimation FR
~3.5 chars/token). Pour chaque document, par ordre de score :

| Priorité | Contenu | Condition |
|---|---|---|
| 1 | **Document ENTIER** (tous les chunks L1 `semantic_leaf`, ordre `page_no` puis `chunk_index`) | taille ≤ `CAG_FULL_DOC_MAX_TOKENS` (défaut 20k) ET budget restant suffisant |
| 2 | **Fenêtre de pages** : pages matchées ± `CAG_PAGE_RADIUS` (défaut 3), fusion des fenêtres qui se chevauchent | document trop grand pour la prio 1 |
| 3 | **Chunks d'enrichissement L2** du document (synthèses inter-pages) | budget restant |
| 4 | Documents suivants (au-delà du top pack) : **page matchée seule** | budget restant |

- Dédupe stricte (document_id, page_no).
- Arrêt quand le budget est consommé ; toujours inclure au minimum le doc n°1 même s'il
  faut le fenêtrer.

**Étape C — Rendu structuré**
```
=== DOCUMENT 1 : « Notice de pose seuil PMR 76100 » ===
Source : PROFERM | Type : notice_pose | Gamme : Perform 76 | Matériau : PVC
Pages incluses : 1 à 12 (document complet)

[page 1]
…texte intégral de la page…
[page 2]
…
=== DOCUMENT 2 : « DTA 6/16-2335 V5 » ===
Source : CSTB | Type : avis_technique | Pages incluses : 5-9, 11 (extraits)
…
```
- En-têtes = métadonnées Document (source, product_types, materials, proferm_gammes) →
  c'est ce qui permet au LLM de NE PAS mélanger Perform 70 / 76 malgré le gros contexte.
- Meilleur document en PREMIER (les LLM privilégient début de contexte), et la question
  utilisateur est répétée APRÈS le contexte (anti « lost in the middle »).

**Étape D — Images (si modèle vision)**
- Pages schéma/procédurales parmi les pages incluses : PNG top `CAG_MAX_IMAGES` (défaut 8),
  priorisées par score de page + `section_type ∈ {diagram, step}`.

### 2.2 Adaptation du prompt système

Le prompt actuel raisonne « chunks/passages ». À réécrire pour le mode CAG :
- « Tu reçois des DOCUMENTS complets ou des extraits étendus, chacun avec son en-tête
  (source, gamme, matériau) et ses numéros de page. »
- Conserver le hard grounding tel quel (il est bon), MAIS remplacer « le chunk » par
  « le document » et ajouter : « Vérifie l'en-tête du document avant d'attribuer une
  valeur à une gamme : ne transfère jamais une cote d'un document Perform 70 vers une
  question Perform 76. »
- Résolution de conflit inchangée (document le plus spécifique prime).

### 2.3 Sources côté UI

- Afficher les sources **par document** avec les pages incluses (au lieu de 8 badges chunk) :
  `[1] Notice seuil PMR 76100 (complet)` `[2] DTA 6/16-2335 (p.5-9, 11)`.
- Phase 3 (optionnel) : demander au modèle un bloc final masqué
  `<sources>{"used":[{"doc":1,"pages":[3,4]}]}</sources>` pour n'afficher que les sources
  réellement UTILISÉES — remplace l'actuel fallback « sources par score » (imprécis).

### 2.4 Configuration (nouvelles clés)

```python
CAG_ENABLED: bool = true                 # flag global, fallback = pipeline passages actuel
CAG_TOKEN_BUDGET: int = 100_000          # budget contexte documentaire (tokens estimés)
CAG_MAX_DOCUMENTS: int = 8               # top-D documents agrégés
CAG_FULL_DOC_MAX_TOKENS: int = 20_000    # au-delà → fenêtrage par pages
CAG_PAGE_RADIUS: int = 3                 # fenêtre autour des pages matchées (gros docs)
CAG_MAX_IMAGES: int = 8                  # pages PNG jointes (modèle vision)
CAG_CHARS_PER_TOKEN: float = 3.5         # estimation FR pour le packing
```
Et : `RAG_POOL_SIZE` 20 → **60** (plus de pages votantes par document), `RAG_TOP_K`
devient sans effet en mode CAG (remplacé par le budget).

## 3. Coût, latence, risques — et leurs parades

| Enjeu | Réalité | Parade |
|---|---|---|
| **Coût** | ~100k tokens input ≈ 0,20–0,40 €/requête sur Mistral Large | Budget par défaut 100k (pas 200k) ; mode `eco` 40k configurable ; monitoring tokens/requête dans les traces |
| **Latence prefill** | 100k tokens ≈ +3–8 s avant 1er token | Acceptable vs gain qualité ; compensée par la fusion des appels LLM déjà faite (-4 s) ; packing = SQL simple (rapide) |
| **« Lost in the middle »** | Info noyée au milieu du contexte | Meilleur doc en premier, question répétée en fin, en-têtes/pages explicites |
| **Mélange de gammes** | Perform 70 et 76 dans le même contexte | En-têtes documentaires (gamme/matériau) + règle prompt renforcée ; le retriever met rarement 2 gammes si la requête est précise |
| **Docs OCR bruités volumineux** | Un gros doc mal extrait consomme le budget | `CAG_FULL_DOC_MAX_TOKENS` + fenêtrage ; prio aux docs à score fort |
| **Régression** | — | Flag `CAG_ENABLED` ; A/B avec `retriever_evaluator.py` (les stages d'éval existent déjà) |

Note modèle : la génération doit bien pointer sur **Mistral Large 3** (256k, vision) via
`MODEL_FAST` — vérifier l'env (`MODEL_FAST=mistral-large-latest`) ; le plancher
`max_tokens` 2048 est déjà en place, monter à 3000–4096 en mode CAG
(`CAG_MAX_COMPLETION_TOKENS`) pour les réponses procédurales complètes.

## 4. Phases d'implémentation

### Phase 0 — Quick win immédiat (5 min, sans code)
- `RAG_TOP_K` 8 → **20** et `RAG_POOL_SIZE` 20 → 40 dans compose.
- Effet : 20 pages entières au lieu de 8 dès maintenant (~25-60k chars), pendant que la
  refonte se construit. Zéro risque (budget chars 80k déjà en place).

### Phase 1 — Context packer (cœur de la refonte)
- `context_packer_service.py` : agrégation doc + packing budget + rendu structuré
  (Étapes A-B-C). Branché dans `search_multimodal_passages` derrière `CAG_ENABLED`
  (remplace la coupe `[:top_k]` + `format_multimodal_passages` quand actif).
- Prompt système variante CAG dans `chat.py`.
- Tests : agrégation (multi-pages > page unique forte ?), packing (budget respecté,
  full-doc vs fenêtre, dédupe), rendu (ordre lecture, en-têtes, marqueurs pages).

### Phase 2 — Sources doc-level + images
- `sources_data` par document avec pages incluses ; UI : badges document.
- Sélection d'images par `section_type` ; cap `CAG_MAX_IMAGES`.
- Tests : mapping sources, cap images.

### Phase 3 — Précision et pilotage
- Bloc `<sources>` JSON en fin de génération → sources réellement utilisées.
- Budget adaptatif : si la réponse contient « la notice ne précise pas » ET que des
  documents restaient hors budget → 2ᵉ passe automatique budget max (self-escalation),
  ou bouton UI « chercher plus loin ».
- Éval A/B : recall@doc, groundedness, coût moyen/requête, latence P50/P95.

### Phase 4 — Optimisation
- Cache du texte assemblé par document (table `document_fulltext` ou fichier) pour éviter
  de re-concaténer 60 chunks à chaque requête (latence packing → ~0).
- Tuning budgets par type de requête (fiche technique → eco ; diagnostic SAV → max).

## 5. Ce que ça change concrètement sur votre exemple

## RÉALISÉ (2026-07-02) — Ancrage conversation + CAG Phase 1

### Diagnostic « 12 max » confirmé
Aucun cap code à 12 : `RERANK_POOL=100`, `pool_size=100`, seule coupe `fused_hits[:top_k=20]`.
Le « 12 » = pages distinctes réellement qualifiantes (seuils par canal + convergence RRF +
taille du corpus). `top_k` n'est plus le goulot → d'où le CAG.

### Ancrage documentaire conversationnel ✅ (flag `CONVERSATION_ANCHOR_ENABLED`)
- `compute_anchor_documents` : documents dominants d'un tour (top-N par score cumulé), persistés
  dans `query_context.current_documents`.
- `apply_anchor_boost_to_fused_hits` : au tour suivant (hors `topic_shift`), les pages de ces
  documents sont boostées AVANT la coupe top_k → la conversation reste sur le même produit.
- Câblé dans `chat.py` (calcul post-retrieval + réutilisation pré-retrieval) et propagé via
  `search_technical_passages → search_relevant_passages → search_multimodal_passages`.
- Tests : `tests/test_conversation_anchor.py`.

### CAG Phase 1 ✅ (flag `CAG_ENABLED`)
- `app/services/context_packer_service.py` : `aggregate_documents` (passages → top-D documents)
  + `build_cag_context` (documents ENTIERS sous budget, sinon fenêtrés ± `CAG_PAGE_RADIUS`),
  rendu structuré avec en-têtes (source/gamme/matériau) + marqueurs `[page N]` + préambule
  anti-mélange de gammes.
- Budgets : `CAG_TOKEN_BUDGET=100000`, `CAG_MAX_DOCUMENTS=8`, `CAG_FULL_DOC_MAX_TOKENS=20000`.
- Intégré dans `chat.py` via `_build_generation_context` (CAG si activé, sinon passages) —
  le retrieval est inchangé, seule l'étape de construction du contexte change.
- Tests : `tests/test_cag_context_packer.py`.

### Restant (prochaines phases)
- **Guided flow & fiche technique** doivent aussi respecter l'ancre (sinon un tour « guidé »
  peut encore sauter de produit — cf. INNOSLIDE dans l'exemple). À câbler.
- **Sources UI par document** (Phase 2) : afficher `cag_documents` (doc + pages incluses) au
  lieu des badges par page.
- **Bloc `<sources>` JSON** (Phase 3) + budget adaptatif + cache texte par document (Phase 4).

### Ops
- Redémarrer le conteneur web pour recharger le code (`docker compose up -d --force-recreate web`).
  `CAG_ENABLED` et `CONVERSATION_ANCHOR_ENABLED` valent true par défaut (absents de compose).
